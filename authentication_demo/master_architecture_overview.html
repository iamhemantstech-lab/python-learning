Phase 1: Registration Flow Create New User Account
1
POST
/auth/register
Frontend sends JSON body: {name, email, password}
UserRegister Schema
2
SECURITY
FastAPI hashes plain password using Argon2id (pwdlib) & commits to MySQL
INSERT INTO users
3
HTTP 201
FastAPI filters password out via RegisterResponse and returns safe user profile
Password Never Returned
Phase 2: Login & Dual-Token Issuance 15-Min Access Token + 7-Day Refresh Token
4
POST
/auth/login
Frontend sends credentials: {email, password}
UserLogin Schema
5
VERIFY
FastAPI verifies Argon2 hash in DB, creates Access Token (15m) + Refresh Token (7d)
Save Refresh Token in MySQL
6
HTTP 200
Returns {access_token, refresh_token, token_type: "bearer"}. Frontend stores securely
Memory / HttpOnly Cookie
Phase 3: Accessing Protected Routes (Fast & Stateless) Minutes 0 to 15 (Normal Usage)
7
GET
/auth/me
Frontend attaches header: Authorization: Bearer <access_token>
HTTPBearer Extractor
8
VERIFY
HTTPBearer & decode_access_token verify JWT signature in memory (Zero DB overhead)
⚡ Verified in Microseconds
9
HTTP 200
FastAPI returns requested user profile / protected data to frontend
UserResponse Model
Phase 4: Silent Token Refresh (The Magic Moment) Triggered Automatically When 15-Min Token Expires
10
HTTP 401
At min 16, request to /auth/me fails with 401 Unauthorized ("Token expired")
Access Token Expired
11
POST
/auth/refresh
Axios Interceptor catches 401 silently and sends Refresh Token to get a fresh Access Token
Silent Refresh Behind Scenes
12
DB CHECK
FastAPI checks MySQL: Is refresh_token valid and not revoked? If valid, generates new Access Token
SELECT FROM refresh_tokens
13
HTTP 200
Frontend receives new 15-min Access Token & automatically retries original request. User sees no disruption!
Zero User Friction ✨
Phase 5: Logout & Revocation Instant Invalidation
14
POST
/auth/logout
User clicks "Log Out" $\rightarrow$ Frontend sends Refresh Token to logout endpoint
Terminate Session
15
REVOKE
FastAPI marks is_revoked = True or deletes token from MySQL. Frontend clears storage
Token Permanently Killed 🔒
⚡ 1. High Performance
99% of requests use the 15-min Access Token verified in memory in microseconds with zero database queries.
🛡️ 2. Maximum Security
If an access token leaks, it dies in 15 minutes. Passwords hashed with state-of-the-art Argon2id.
🔒 3. Total Revocation Control
Because refresh tokens live in MySQL, you can force logouts, support multiple devices, and kill stolen tokens.
